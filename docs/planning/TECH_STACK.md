## Compatibility probe acceptance

The probe belongs in an isolated tooling directory, not final UI. It should:

1. Use the requested AGP/Gradle/Kotlin pins, exact catalog dependencies and checked wrapper checksum. Print runtime and resolved plugin/compiler information.
2. Compile a minimal Android target with a harmless Compose function and an explicitly pinned Material 3 API, without designing final application screens.
3. Compile Room 3 entity, coroutine DAO and database; verify generated implementation and exported schema. Resolution alone does not prove KSP processing.
4. Exercise Koin compiler DSL or annotations and actually resolve a dependency. Official docs warn placeholder DSL functions may compile yet throw `NotImplementedError` when the compiler transformation is absent.
5. Exercise serialization generation and raw JSON handling in a JVM/unit check, and resolve DataStore/Ktor/Coroutines/Coil together so version conflicts are visible.
6. Record exact commands, exit codes, warnings, selected JDK/SDK, generated artifacts and passing/failing stages. No credentials, Gemini calls, signing or publication.

A passing probe is local compatibility evidence for the tested configuration, not proof of runtime storage/security, device accessibility, production reliability, or SillyTavern format support. The supervisor accepted this evidence for starting the product foundation while retaining the support exceptions. The actual product modules, debug APK, JVM tests, lint and hosted CI were subsequently verified; M0 is complete for the internal build. Product runtime and interoperability checks remain pending.
